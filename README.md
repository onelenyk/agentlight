# AgentLight

Маленька лампа на ESP32-C3 Super Mini, яка кольором показує, що зараз робить AI-агент. Стоїть на столі, живиться від USB-C, статуси отримує по WiFi від хуків Claude Code або як MCP-сервер.

![Корпус у зборі](docs/images/case-preview.png)

| Світло | Що означає |
|---|---|
| оранжевий, «дихає» | агент працює |
| червоний, блимає | агент чекає на тебе: дозвіл або питання |
| червоний, рівний | помилка |
| зелений | готово |
| синій, «дихає» | лампа чекає налаштування WiFi |
| фіолетовий, «дихає» | немає WiFi |

Якщо агентів кілька, лампа показує найважливіший стан: помилка > чекає > працює > готово.

## Зібрати свою

1. **Купити деталі** — [список компонентів](docs/bom.md): плата, три діоди на круглих платках, сенсорна кнопка, резистор, дріт.
2. **Надрукувати корпус** — п'ять деталей у трьох кольорах, без підтримок: [файли й налаштування](docs/case.md).
3. **Спаяти** — [схема й порядок пайки](docs/wiring.md).
4. **Прошити** — `cd firmware && pio run -t upload`: [прошивка](docs/firmware.md).
5. **Підключити до WiFi** — по Bluetooth зі сторінки `web/setup.html` або через точку доступу лампи: [сайт](docs/site.md).
6. **Під'єднати агента** — одна команда зі сторінки лампи: [підключення агентів](docs/hooks.md).

![Схема підключення](docs/images/wiring.png)

## Швидкий старт на новій машині

```sh
git clone <адреса репозиторію> agentlight && cd agentlight

python3 web/serve.py                       # сайт: http://localhost:8791/web/

cd firmware && pio run -t upload           # прошивка (потрібен PlatformIO)

python3 -m venv .venv && .venv/bin/pip install -r case/requirements.txt
.venv/bin/python case/build.py             # перебудувати корпус
.venv/bin/python case/verify.py            # перевірити його
```

## Стан проєкту

### Агенти

| Агент | Тестували на справжній програмі | Не тестували |
|---|---|---|
| Claude Code | усі стани в щоденній роботі, кілька сесій одночасно; встановлення командою з лампи | — |
| OpenCode | «працює» (із запитом і назвою інструмента), «готово» | запит дозволу, питання, помилку, переривання |
| Antigravity IDE | «працює», «готово» | помилку, фонові задачі; стану «чекає» немає взагалі |
| Codex CLI | «працює», закриття сесії (без входу в акаунт) | «готово», «чекає» |
| Qwen Code | «працює» (без входу в акаунт) | решту станів |
| Copilot CLI | — | усе: без входу в GitHub не запускається |
| Cursor | — | усе: програми не було |
| Gemini CLI | — | усе: не запускається без платного ключа |

Для всіх восьми перевірено встановлювач (у порожній домашній теці) і розбір подій лампою на пробних подіях у форматі кожного агента. Деталі — у [docs/hooks.md](docs/hooks.md).

### Лампа

Тестували:

- «Дозволити» (експериментально) на справжній лампі: спарювання, дозвіл, відмова, відмова пропонувати небезпечну команду й вимкнену групу, вихід часу, два запити одразу, чужий ключ, перевірка підпису. На справжньому Claude Code: дозволена з лампи команда виконалась, відхилена — ні, без відповіді Claude Code повернувся до звичайного порядку. Дотик у цих перевірках імітувала спеціальна збірка прошивки; у випущених збірках такого шляху немає.
- Ігри: марафон, кубик, реакція з фальстартом і «10 секунд» пройдені запитами до лампи; рекорди переживають перезавантаження.
- Режими «стан агентів», «лампа» і «фокус»: таймер вимкнення, таймер сну, таймер фокусу з переходом від роботи до перерви, сигнал агентові, запит на адресу, налаштування кольорів, анімацій і дотику — запитами до лампи.
- Сторінку лампи у справжньому Chrome: перемикання режимів, список агентів із командою встановлення, розділ «Пристрій», задання пароля й оновлення прошивки через форму (файл залився з прогресом, лампа перезавантажилась).
- Сенсор: дотики рахуються; перемикання яскравості утриманням.
- WiFi: налаштування через точку доступу, повернення в мережу після перезавантаження, вибір потрібної мережі з кількох збережених.
- Bluetooth: лампа знаходиться з Mac, віддає стан і список мереж, додає й забуває мережу (скриптом, тим самим протоколом, що й сторінка).
- Сторінку налаштування на https://agentlight.onelenyk.dev/: відкривається по HTTPS, вміст збігається з `web/setup.html`.
- MCP: Claude Code підключається до лампи як до MCP-сервера, бачить обидва інструменти й викликає `set_status` — лампа показує переданий стан.
- Оновлення по WiFi: через сторінку, запитом і через PlatformIO, щоразу з перевіркою, що запустилась саме нова збірка. Лампа відхиляє невірний пароль, файл-сміття, обрізану прошивку, змінений файл і підпис чужим ключем.
- Збереження налаштувань між версіями прошивки.
- Сторінку Bluetooth у Chrome: кнопка «Знайти лампу» знаходить лампу й підключається.
- Корпус: надрукований і зібраний, деталі сидять добре, зокрема розсіювач із гніздом під сенсор під закрученим ковпаком.

Не тестували:

- «Дозволити»: живий дотик до сенсора під час запиту; чи видно питання у вікні Claude Code, поки лампа чекає; відповідь лампи в інтерактивному OpenCode (плагін шле запит і знімає його, але саму відповідь через лампу перевірити не вдалося — у неінтерактивному режимі OpenCode відхиляє питання сам).
- Пульт: лампа оголошує себе Bluetooth-клавіатурою, але спарювання з комп'ютером і доставку клавіш ніхто не пробував.
- На самому сенсорі: подвійний дотик, вибір режиму довгим утриманням, дії в режимах лампи й фокусу. Розпізнавання жестів перевірене лише тестами на комп'ютері.
- Як таймер фокусу й ігри виглядають на діодах і чи зручно в них грати: логіка ігор перевірена тестами й запитами до лампи, але пальцем ніхто не грав.

Розміри, взяті як типові, а не виміряні: товщина плати ESP (1,0 мм), товщина платки діода (1,2 мм), модуль TTP223 (15 × 11 × 2 мм).

Захисту немає: будь-хто у твоїй мережі WiFi може міняти стан і налаштування лампи, будь-хто поруч із Bluetooth — додати чи забути мережу.
