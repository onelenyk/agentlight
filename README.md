# AgentLight

Маленька лампа на ESP32-C3 Super Mini, яка кольором показує, що зараз робить AI-агент. Стоїть на столі, живиться від USB-C, статуси отримує по WiFi від хуків Claude Code або як MCP-сервер.

![Корпус у зборі](docs/images/case-preview.png)

| Світло | Що означає |
|---|---|
| оранжевий, «дихає» | агент працює |
| червоний, блимає | агент чекає на тебе: дозвіл або питання |
| червоний, рівний | помилка |
| зелений | готово |
| синій, «дихає» | лампа чекає налаштування WiFi |
| фіолетовий, «дихає» | немає WiFi |

Якщо агентів кілька, лампа показує найважливіший стан: помилка > чекає > працює > готово.

## Зібрати свою

1. **Купити деталі** — [список компонентів](docs/bom.md): плата, три діоди на круглих платках, сенсорна кнопка, резистор, дріт.
2. **Надрукувати корпус** — п'ять деталей у трьох кольорах, без підтримок: [файли й налаштування](docs/case.md).
3. **Спаяти** — [схема й порядок пайки](docs/wiring.md).
4. **Прошити** — `cd firmware && pio run -t upload`: [прошивка](docs/firmware.md).
5. **Підключити до WiFi** — по Bluetooth зі сторінки `web/setup.html` або через точку доступу лампи: [сайт](docs/site.md).
6. **Під'єднати агента** — одна команда зі сторінки лампи: [підключення агентів](docs/hooks.md).

![Схема підключення](docs/images/wiring.png)

## Швидкий старт на новій машині

```sh
git clone <адреса репозиторію> agentlight && cd agentlight

python3 web/serve.py                       # сайт: http://localhost:8791/web/

cd firmware && pio run -t upload           # прошивка (потрібен PlatformIO)

python3 -m venv .venv && .venv/bin/pip install -r case/requirements.txt
.venv/bin/python case/build.py             # перебудувати корпус
.venv/bin/python case/verify.py            # перевірити його
```

## Стан проєкту

### Агенти

| Агент | Тестували на справжній програмі | Не тестували |
|---|---|---|
| Claude Code | усі стани в щоденній роботі, кілька сесій одночасно; встановлення командою з лампи | — |
| OpenCode | «працює» (із запитом і назвою інструмента), «готово» | запит дозволу, питання, помилку, переривання |
| Antigravity IDE | «працює», «готово» | помилку, фонові задачі; стану «чекає» немає взагалі |
| Codex CLI | «працює», закриття сесії (без входу в акаунт) | «готово», «чекає» |
| Qwen Code | «працює» (без входу в акаунт) | решту станів |
| Copilot CLI | — | усе: без входу в GitHub не запускається |
| Cursor | — | усе: програми не було |
| Gemini CLI | — | усе: не запускається без платного ключа |

Для всіх восьми перевірено встановлювач (у порожній домашній теці) і розбір подій лампою на пробних подіях у форматі кожного агента. Деталі — у [docs/hooks.md](docs/hooks.md).

### Лампа

Тестували:

- Режими «стан агентів» і «лампа», таймер вимкнення, налаштування кольорів, анімацій і дотику — запитами до лампи; сторінку в обох режимах — на знімку.
- Сенсор: дотики рахуються; перемикання яскравості утриманням.
- WiFi: налаштування через точку доступу, повернення в мережу після перезавантаження.
- Bluetooth: лампа знаходиться з Mac, віддає стан і список мереж (скриптом).
- Оновлення по WiFi: через запит до лампи і через PlatformIO; невірний пароль і файл-сміття відхиляються.
- Збереження налаштувань між версіями прошивки.

Не тестували:

- Подвійний дотик і дії сенсора в режимі лампи — на самому сенсорі.
- Кілька збережених мереж WiFi: вибір між ними.
- Сторінку `web/setup.html` у Chrome: додавання мережі по Bluetooth.
- Форму оновлення прошивки на сторінці лампи (сам запит — тестували).
- MCP як сервер у Claude Code: лише запитами curl.
- Посадки корпусу після останніх змін розсіювача.

Розміри, взяті як типові, а не виміряні: товщина плати ESP (1,0 мм), товщина платки діода (1,2 мм), модуль TTP223 (15 × 11 × 2 мм).

Захисту немає: будь-хто у твоїй мережі WiFi може міняти стан і налаштування лампи, будь-хто поруч із Bluetooth — додати чи забути мережу.
