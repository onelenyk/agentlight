# Тести

Усе, що з'єднує агентів із лампою, перевіряється без самої лампи — локально й у GitHub Actions.

```sh
python3 -m unittest discover -s tests -v    # ~7 секунд; потрібні python3, компілятор C++, curl, node
python3 tests/canary.py                     # справжні CLI агентів; потрібні node і npm, ~1 хвилина
```

## Що перевіряється на кожен коміт

Файл `.github/workflows/ci.yml`, три завдання.

**Хуки, розбір подій, встановлювач** (`tests/test_agentlight.py`):

| Група | Що ловить |
|---|---|
| розбір подій | лампа неправильно зрозуміла подію агента: не той стан, сесія, проєкт, запит чи дія. 30 зразків подій у `tests/hook_cases.json` для семи агентів, зокрема обрізані посередині, з українським текстом, з порожнім тілом |
| файли хуків | файл `hooks/<агент>.json` має форму, яку агент не прийме, або шле не на ту адресу лампи. Тут зафіксована форма, на якій уже спіткнулись: Antigravity відкидав увесь файл через зайвий рівень вкладеності |
| встановлювач | `install.sh` затер чужі хуки чи налаштування, продублював свої при повторному запуску, зіпсував файл без `python3` і `node`, перезаписав пошкоджений файл |
| наскрізний шлях | встановлений хук, запущений як його запускає агент, не доходить до лампи, друкує зайве або затримує агента, коли лампа вимкнена |

Розбір подій — це той самий файл `firmware/src/hook_parse.h`, що йде в прошивку: тести збирають його на комп'ютері (`tests/hookparse.cpp`). Замість лампи працює `tests/mock_lamp.py` з тими самими адресами; файли він, як і лампа, віддає стиснутими.

**Збірка прошивки.** Обидві прошивки збираються; збірка падає і тоді, коли прошивка перестає влазити в слот 1,25 МБ.

**Корпус.** Модель перебудовується й проходить `case/verify.py`.

## Що перевіряється раз на тиждень

Файл `.github/workflows/canary.yml`, скрипт `tests/canary.py`. Він ставить найсвіжіші Codex CLI і Qwen Code, підключає їх встановлювачем до імітації лампи й запускає по одному запиту без входу в акаунт. До відповіді моделі не доходить, але хук «запит надіслано» спрацьовує раніше.

Червоний запуск означає: агент змінив формат хуків чи подій, і з його новою версією лампа, найімовірніше, мовчить.

## Чого тести не бачать

- **Саму лампу:** діоди, сенсор, WiFi, сторінку в браузері, оновлення по WiFi. Це перевіряється руками.
- **Агентів, яких не запустити без акаунта чи вікна:** Claude Code, OpenCode, Antigravity, Copilot CLI, Cursor, Gemini CLI. Для них тести фіксують лише формат, який ми вже бачили робочим або взяли з документації; зміну формату з боку агента вони не помітять.
- **Стани після запиту до моделі** («готово», «чекає», «помилка») у Codex і Qwen: без входу в акаунт до них не дійти.
- **Вміст прошивки, крім розбору подій:** режими, анімації, таймери, API налаштувань тестами не покриті.

## Як додати зразок події

Коли агент прислав подію, яку лампа зрозуміла не так: додай її в `tests/hook_cases.json` з очікуваним результатом, переконайся, що тест падає, і виправ `firmware/src/hook_parse.h`.
