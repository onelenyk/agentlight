# Тести

Усе, що з'єднує агентів із лампою, перевіряється без самої лампи — локально й у GitHub Actions.

```sh
python3 -m unittest discover -s tests -v    # ~7 секунд; потрібні python3, компілятор C++, curl, openssl, node
python3 tests/canary.py                     # справжні CLI агентів; потрібні node і npm, ~1,5 хвилини
```

## Що перевіряється на кожен коміт

Файл `.github/workflows/ci.yml`, три завдання.

**Хуки, розбір подій, встановлювач** (`tests/test_agentlight.py`):

| Група | Що ловить |
|---|---|
| розбір подій | лампа неправильно зрозуміла подію агента: не той стан, сесія, проєкт, запит чи дія. 30 зразків подій у `tests/hook_cases.json` для семи агентів, зокрема обрізані посередині, з українським текстом, з порожнім тілом |
| файли хуків | файл `hooks/<агент>.json` має форму, яку агент не прийме, або шле не на ту адресу лампи. Тут зафіксована форма, на якій уже спіткнулись: Antigravity відкидав увесь файл через зайвий рівень вкладеності |
| встановлювач | `install.sh` затер чужі хуки чи налаштування, продублював свої при повторному запуску, зіпсував файл без `python3` і `node`, перезаписав пошкоджений файл |
| наскрізний шлях | встановлений хук, запущений як його запускає агент, не доходить до лампи, друкує зайве або затримує агента, коли лампа вимкнена |
| жести й таймер фокусу | дотик розпізнано не так (подвійний замість двох окремих, утримання замість вибору режиму), таймер рахує під час паузи, не переходить між роботою й перервою, ламається на переповненні лічильника часу |
| реліз прошивки | підпис не сходиться з файлом, `latest.json` описує не той файл, у репозиторій потрапив закритий ключ, сторінка лампи й процес публікації розійшлись в адресі оновлень |

Розбір подій — це той самий файл `firmware/src/hook_parse.h`, що йде в прошивку: тести збирають його на комп'ютері (`tests/hookparse.cpp`). Замість лампи працює `tests/mock_lamp.py` з тими самими адресами; файли він, як і лампа, віддає стиснутими.

**Збірка прошивки.** Обидві прошивки збираються; збірка падає і тоді, коли прошивка перестає влазити в слот 1,25 МБ.

**Корпус.** Модель перебудовується й проходить `case/verify.py`.

## Що перевіряється раз на тиждень

Файл `.github/workflows/canary.yml`, скрипт `tests/canary.py`. Він ставить найсвіжіші версії справжніх CLI, підключає їх нашим встановлювачем до імітації лампи й запускає без входу в акаунт.

| Агент | Як запускається | Що перевіряє |
|---|---|---|
| Claude Code | повні ходи проти імітації API моделі (`tests/mock_model.py`): відповідь, виклик інструмента, помилка API | що Claude Code читає наш файл хуків і шле лампі «працює» із запитом і проєктом, дію інструмента, «готово», «помилку», «спокій» після закриття сесії |
| Codex CLI | один запит; запит до OpenAI падає з 401 | що Codex приймає файл хуків і шле «працює» із запитом і проєктом, а після завершення — «спокій» |
| Qwen Code | один запит до недосяжного сервера | що Qwen приймає файл хуків і шле «працює» із запитом і проєктом |

Червоний запуск означає: агент змінив формат файлу хуків чи полів події, і з його новою версією лампа, найімовірніше, показує не те. Перевірено навмисною поломкою: якщо зіпсувати форму запису `Stop` у `hooks/claude.json`, канарка падає, бо «готово» не приходить.

Особливості:

- **Claude Code запускається через потоковий інтерфейс**, а не `claude -p "..."`: у звичайному неінтерактивному запуску фонові хуки кінця ходу обриває вихід із програми.
- **Імітація моделі відповідає з паузою пів секунди.** Хуки фонові, тож «запит надіслано» і «хід завершено», надіслані майже одночасно, можуть дійти до лампи в зворотному порядку — тоді лампа лишилась би в «працює». Справжня модель думає довше, ніж іде запит до лампи, тому в житті цього не видно, але гарантії порядку немає.
- **Помилка API в тесті — 400.** Помилки 401, 429 і 5xx Claude Code повторює хвилинами, перш ніж здатися.

## Чого тести не бачать

- **Саму лампу:** діоди, сенсор, WiFi, сторінку в браузері, оновлення по WiFi. Це перевіряється руками.
- **Стан «чекає»** на справжніх агентах: запит дозволу з'являється лише в інтерактивному вікні.
- **Агентів, яких не запустити без акаунта чи вікна:** OpenCode, Antigravity, Copilot CLI, Cursor, Gemini CLI. Для них тести фіксують лише формат, який ми вже бачили робочим або взяли з документації; зміну формату з боку агента вони не помітять.
- **Стани після запиту до моделі** в Codex і Qwen: для них немає імітації моделі.
- **Вміст прошивки, крім розбору подій:** режими, анімації, таймери, API налаштувань тестами не покриті.

## Як додати зразок події

Коли агент прислав подію, яку лампа зрозуміла не так: додай її в `tests/hook_cases.json` з очікуваним результатом, переконайся, що тест падає, і виправ `firmware/src/hook_parse.h`.
