# Звіт наскрізної перевірки

Дата: 9 жовтня 2026. Прошивка: 0.12.0. Лампа: `AgentLight-4750` (ESP32-C3 Super Mini, три діоди, сенсор TTP223), у домашній мережі WiFi.

## Підсумок

**67 перевірок із 68 пройшли, одна пропущена, жодна не впала.** Перевірено все, що можна перевірити без пальця на сенсорі й без очей: лампа через мережу, справжні програми агентів, оновлення прошивки, Bluetooth, сайт.

Пропущена перевірка — «клавіша гучності з лампи міняє гучність цього Mac»: під час прогону активним пристроєм пульта був iPad. Те, що клавіші отримує лише вибраний пристрій, підтвердила сусідня перевірка.

Це другий повний прогін. Перший, на версії 0.11.0, знайшов три справжні вади; вони виправлені в 0.11.1. Нинішній нових вад лампи не знайшов, але показав дві слабкості самої перевірки — про них нижче.

Чого ця перевірка не охоплює — у розділі «Що лишилось перевірити руками»: насамперед жести на живому сенсорі та вигляд світла.

## Як перевіряли

Усі перевірки зібрані в `tests/e2e_lamp.py` і запускаються однією командою проти живої лампи:

```sh
python3 tests/e2e_lamp.py --lamp 192.168.110.67
```

Що в ній справжнє, а що ні:

| Що | Справжнє | Замінено |
|---|---|---|
| Лампа | так: справжня плата в мережі, справжня прошивка | — |
| Claude Code 2.1.295, Codex CLI 0.162.0, Qwen Code 0.25.0, OpenCode 1.18.35 | так: свіжі версії справжніх програм, хуки поставлені встановлювачем із лампи | модель: замість API стоїть імітація на тому ж комп'ютері, тож акаунт і гроші не потрібні. Codex і Qwen запускались без входу в акаунт і до відповіді моделі не доходять |
| Оновлення прошивки | так: лампа справді перепрошивалась понад десять разів, і щоразу звірявся час збірки | — |
| Bluetooth | так: пошук, читання й запис із цього Mac; два спаровані пристрої (Mac та iPad), і клавіша гучності з лампи міняє гучність Mac лише тоді, коли активний він | — |
| Дотик до сенсора | **ні** | у розділі «Дозволити» дотик імітувала окрема збірка прошивки з прапорцем `ALLOW_TEST_TOUCH`. У випущених збірках такого шляху немає, і це теж перевірено |
| Очі | **ні** | колір і анімацію діодів перевірка не бачить — лише те, що лампа каже про свій стан |

Додатково сторінку лампи пройдено у справжньому Chrome: перемикання всіх п'яти режимів, запуск і скидання таймера, вибір гри й дотик зі сторінки, зміна кольору лампи, стан пульта, перевірка оновлень, розділ «Дозволити». Помилок на сторінці не було.

Окремо від цього на кожен коміт у GitHub Actions ідуть 40 автотестів без лампи (`tests/test_agentlight.py`) і раз на тиждень — перевірка на свіжих версіях програм агентів (`tests/canary.py`). Обидва зелені.

## Що знайшла перевірка

### Цей прогін, 0.12.0

Вад лампи не знайдено. Дві слабкості самої перевірки, обидві виправлені:

- **Оновлення через PlatformIO один раз не пройшло.** Вручну пройшло одразу, за 39 секунд, і в наступних трьох прогонах теж. Схоже, одразу після навмисно відхиленої спроби з невірним паролем лампа ще не готова прийняти наступну; справжня причина не встановлена. Перевірка тепер робить одну повторну спробу й пише, якщо вона знадобилась.
- **Після тієї невдачі на лампі лишився тестовий пароль оновлення**, якого вже ніхто не знав: перевірка не дійшла до свого прибирання. Оновлення однією кнопкою це не зачіпало, але свій файл залити стало б неможливо. Пароль знято службовою підписаною збіркою, яка стирає його при запуску. Перевірка тепер має сталий пароль і знімає його окремим кроком за будь-якого результату.

Побічний результат: у прошивці з'явився спосіб зняти забутий пароль оновлення без стирання всієї лампи — підписаною збіркою з прапорцем `OTA_FORGET_PASSWORD`. Зібрати й підписати таку може лише власник ключа підпису.

### Перший прогін, 0.11.0

Справжні вади, виправлені в 0.11.1:

| Вада | Наслідок для власника | Виправлення |
|---|---|---|
| Плагін OpenCode не діставав до лампи за іменем `agentlight.local` | з коробки OpenCode на Mac лампу не засвічував узагалі: пошук імені тривав 5 секунд, а плагін чекав 2 | плагін сам шукає лампу лише в IPv4 (9 мс) і шле стани по одному, в порядку появи |
| Лампу не було видно по Bluetooth, поки до неї підключений спарований комп'ютер | після спарювання пульта ніхто інший не міг знайти лампу, щоб налаштувати WiFi | лампа сама відновлює оголошення, поки є вільне з'єднання |
| «Спокій» від Claude Code при виході надсилав фоновий процес, який вихід міг обірвати | закрита сесія могла висіти на лампі до кінця свого часу | хук кінця сесії тепер сам чекає на запит, до секунди |

Про третю чесно: чи губився «спокій» насправді, я не встановив — у перших прогонах його відсутність пояснювалась помилкою самої перевірки. Виправлення зроблене за документацією Claude Code, яка каже, що фонові хуки при виході обриваються.

Помилки самої перевірки (лампа поводилась правильно):

- перевірка плутала тестову сесію Claude Code зі справжньою, яка в цей час теж була на лампі;
- відповідь «202» від лампи вона приймала за «200»;
- сайт за Cloudflare відхиляв її запит через спосіб звернення.

Ще одне спостереження з роботи, не вада: macOS, уперше побачивши лампу як клавіатуру, просить натиснути клавіші біля Shift. У 0.11.1 на сторінці лампи з'явились дві кнопки, що їх натискають.

## Що лишилось перевірити руками

Це те, чого перевірка не може зробити в принципі:

| Що | Чому не перевірено | Як перевірити |
|---|---|---|
| Жести на сенсорі: дотик, подвійний дотик, утримання, вибір режиму утриманням 2 с | потрібен палець; розпізнавання жестів перевірене лише тестами на комп'ютері | торкнутись і подивитись |
| Як виглядають анімації, таймер фокусу, ігри, кольори режимів | потрібні очі | перемкнути й подивитись |
| Ігри «Стоп-вогник» і «Ритм» | на швидкість і ритм через мережу не зіграти; їхня логіка під тестами | зіграти пальцем |
| «Дозволити» з живим дотиком | дотик імітувала перевірна збірка | увімкнути й дозволити щось агентові |
| Чи видно питання у вікні Claude Code, поки лампа чекає дотику | перевірка йшла без вікна | подивитись при живій роботі |
| Відповідь лампи в інтерактивному OpenCode | без вікна OpenCode сам відхиляє питання за мить | те саме |
| Antigravity | його агент запускається лише з вікна; раніше перевірено вручну: «працює» і «готово» | — |
| Copilot CLI, Cursor, Gemini CLI | не запускаються без акаунта або не встановлені | потрібен вхід у відповідний акаунт |
| Клавіші F13–F16 і керування треками | перевірено лише гучність: вона єдина, чий результат видно програмно. Керування музикою з iPad власник пробував сам | прив'язати команду й торкнутись |
| Налаштування WiFi зі сторінки в Chrome | вибір пристрою потребує кліку людини; сам протокол перевірено скриптом, а кнопку власник перевіряв раніше | — |
| Точка доступу для першого налаштування | перевірка не може перемкнути WiFi цього Mac; власник проходив цей шлях після повного стирання лампи | — |
| Зникнення живлення посеред оновлення | не пробували | — |

## Стан лампи після перевірки

- Прошивка 0.12.0, зібрана й підписана в GitHub Actions (не локальна збірка).
- Мережа, кольори, анімації, дії сенсора — як були до перевірки.
- «Дозволити» вимкнено, спарованих для нього комп'ютерів немає; пароль оновлення не заданий.
- Лампа спарована як Bluetooth-пульт із Mac та iPad; активний — iPad, як вибрав власник.
