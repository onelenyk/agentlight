## «Дозволити»: інші агенти

Зроблено для Claude Code й OpenCode; як воно працює і які має запобіжники — у [firmware.md](firmware.md). Далі — що відомо про решту.

Працюватиме лише там, де агент дає хукові чи плагіну вирішувати за користувача. За документацією й вихідним кодом станом на 2026-10-09 (нічого з цього ще не перевірено на справжніх програмах):

| Агент | Може дозволити | Знає, що питання справді з'явиться | Питання в терміналі під час очікування | Висновок |
|---|---|---|---|---|
| OpenCode | так, плагін відповідає на подію `permission.asked` | так | видно; перемагає перша відповідь | найкращий випадок |
| Claude Code | так, хук `PermissionRequest` | так | у документації не сказано — треба перевірити | підходить |
| Codex CLI | так, хук `PermissionRequest` | так | ймовірно, затримується | підходить |
| Qwen Code | так, хук `PermissionRequest` | так | не сказано | підходить |
| Antigravity | так, `PreToolUse` з рішенням | ні | ймовірно, затримується | лише для вузького переліку інструментів: інакше лампа питатиме й про те, що дозволено й так |
| Copilot CLI | так, крім обходу пісочниці | ні: хук спрацьовує до перевірки правил | затримується | те саме |
| Cursor | не підтверджено | ні | — | поки ні |
| Gemini CLI | ні, хук може лише заборонити | ні | — | неможливо |

Якщо хук не відповів чи не встиг, усі придатні агенти показують звичайне питання — тобто відмова лампи не ламає роботу.

Наступні кандидати — Codex CLI і Qwen Code: їхній хук має той самий формат відповіді, що й у Claude Code.

Відома ціна: у Claude Code хук спрацьовує до показу питання, тож з увімкненою функцією кожне питання в терміналі з'являється із затримкою на час очікування дотику.
