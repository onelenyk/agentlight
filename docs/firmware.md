# Прошивка

PlatformIO, фреймворк Arduino, плата `esp32-c3-devkitm-1` (підходить для Super Mini). Бібліотеки: Adafruit NeoPixel, ArduinoJson 7, NimBLE-Arduino. Займає близько 85% слота прошивки (1,11 з 1,31 МБ).

```sh
cd firmware
pio run -t upload              # основна прошивка
pio device monitor             # лог: стан кожні 5 с, адреса лампи
pio run -e touchtest -t upload # тестова: без WiFi, діоди світять, поки палець на сенсорі
AGENTLIGHT_OTA_PASSWORD=... pio run -e ota -t upload   # оновлення по WiFi, без кабелю
```

Піни задаються в `firmware/platformio.ini`: дані діодів `LED_PIN=3`, до `LED_COUNT=10` діодів у ланцюжку, сенсор `TOUCH_PIN=1`.

## Як вона працює

1. **Запуск.** Читає з пам'яті збережені мережі й налаштування, вмикає Bluetooth.
2. **WiFi.** Шукає в ефірі збережені мережі й підключається до найсильнішої з них. Якщо за 20 с не вийшло або мереж немає — піднімає точку доступу `AgentLight-XXXX` з порталом налаштування (192.168.4.1) і світить синім. Якщо мережі збережені, а до порталу ніхто не підключився, через 3 хвилини перезапускається і пробує знову.
3. **Робота.** У мережі лампа доступна як `http://agentlight.local/` і за IP-адресою. Приймає стани, тримає список агентів, 40 разів на секунду вирішує, чим світити.

### Режими

| Режим | Колір під час вибору | Що робить |
|---|---|---|
| `agents` — стан агентів | оранжевий | показує найважливіший стан серед агентів; без WiFi світить фіолетовим, у режимі налаштування — синім |
| `lamp` — лампа | теплий білий | просто світить вибраним кольором і анімацією; може вимкнутись за таймером або плавно згаснути |
| `focus` — фокус | малиновий | відлічує роботу й перерву по колу |
| `games` — ігри | синій | шість ігор на одному сенсорі |

Перемикаються на сторінці або на самій лампі: **тримай сенсор 2 секунди** — лампа по черзі показує кольори режимів, відпусти на потрібному. Світло можна вимкнути в будь-якому режимі. Стани від агентів лампа приймає завжди, навіть коли їх не показує.

### Таймер фокусу

Робота 25 хвилин, перерва 5, далі по колу; тривалості міняються на сторінці. Діоди — це шкала часу, що лишився: гаснуть по одному, поточний тьмяніє. На зміну відрізка лампа 5 секунд блимає. Робота малинова, перерва зелена; на паузі світло «дихає».

Таймер іде в будь-якому режимі — можна перемкнутись на стан агентів і повернутись. Якщо агент чекає, лампа раз на 3 секунди коротко показує це кольором стану; типово під час роботи це вимкнено («не турбувати»).

### Ігри

Дотик — дія в грі, утримання — наступна гра. У цьому режимі дотик спрацьовує в момент торкання, без білого спалаху й без очікування другого дотику. Кожна гра в очікуванні світить своїм кольором.

| Гра | Суть | Результат |
|---|---|---|
| Реакція | червоне — чекай 2–6 секунд; зелене — торкнись якнайшвидше; зарано — фальстарт | мілісекунди, менше — краще |
| Стоп-вогник | вогник біжить по колу, один діод позначений; зупини вогник на ньому, і він побіжить швидше | влучань поспіль |
| 10 секунд | торкнись, лампа згасне; торкнись ще раз рівно через 10 секунд | помилка, менше — краще |
| Ритм | лампа блимає короткі й довгі спалахи — повтори дотиками; щораунду на спалах більше | пройдено раундів |
| Марафон | скільки дотиків за 10 секунд | кількість |
| Кубик | закрутиться й зупиниться: так чи ні, число діодами або випадковий колір | — |

Після раунду лампа кілька секунд показує оцінку кольором: від зеленого (чудово) до червоного. Рекорди зберігаються в пам'яті лампи й видні на сторінці. Якщо агент чекає, лампа нагадує про це коротким спалахом між раундами.

Сенсор TTP223 відповідає із затримкою 60–220 мс, і вона входить у результат «Реакції»: між гравцями чесно, але з іншими вимірювачами реакції не порівнюй.

Логіка ігор (`firmware/src/games.h`) не залежить від плати й перевіряється тестами на комп'ютері.

### Таймер сну

У режимі лампи: світло плавно згасає за задану кількість хвилин (типово 15) і вимикається. Запускається кнопкою на сторінці або дією сенсора; будь-яке перемикання світла його скасовує.

### Агенти і пріоритети

Лампа тримає до 8 записів, по одному на `agent_id`. Показує найважливіший стан серед усіх: помилка > чекає > працює > готово. Стан `idle` запис видаляє.

Кожен запис живе обмежений час від останнього оновлення (типові значення, міняються на сторінці лампи; 0 — не гасне):

| Стан | Час |
|---|---|
| працює | 10 хв |
| готово | 5 хв |
| чекає, помилка | 2 год |

Список живе лише в оперативній пам'яті й зникає після перезавантаження.

### Анімації

Кожному стану і режиму лампи призначається своя анімація — на сторінці лампи. Вибір зберігається одразу, і для стану лампа 6 секунд показує результат. Діоди в корпусі стоять по колу, тому «біжучі» анімації виглядають як обертання.

| Назва | Що робить | Типово для |
|---|---|---|
| `solid` | рівне світло | готово, помилка |
| `breathe` | плавно яскравішає і тьмяніє | працює |
| `blink` | блимає двічі на секунду | чекає |
| `spin` | один вогник біжить по колу | |
| `comet` | вогник із хвостом, плавно | |
| `wave` | хвиля яскравості по колу | |
| `heartbeat` | два удари і пауза | |
| `sparkle` | випадкові спалахи | |
| `pendulum` | вогник туди й назад | |
| `fill` | діоди загоряються по одному, потім гаснуть | |
| `beacon` | два короткі спалахи і пауза | |
| `rainbow` | кольори по колу; власний колір стану не використовується | |

Для біжучих анімацій у розділі «Пристрій» має стояти справжня кількість діодів (типово 3).

### Сенсор

TTP223 на GPIO1. На кожен дотик лампа коротко блимає білим. Жести:

| Жест | Що робить |
|---|---|
| дотик | дія з налаштувань |
| подвійний дотик | дія з налаштувань |
| утримання, від 0,8 с | дія з налаштувань; виконується, коли відпустиш |
| довге утримання, від 2 с | вибір режиму |

Дії призначаються окремо в кожному режимі:

| Дія | Що робить | Де доступна |
|---|---|---|
| `none` | нічого | всюди |
| `dismiss` | «побачив»: прибирає готово, чекає і помилку; агенти в роботі лишаються | стан агентів |
| `brightness` | яскравість по колу: тьмяно → середньо → повна | всюди |
| `toggle` | вимикає й вмикає світло | всюди |
| `mode` | наступний режим | всюди |
| `signal` | сигнал агентові: лічильник у `get_status` збільшується на один | всюди |
| `webhook` | POST на адресу з налаштувань | всюди |
| `spark` | півторасекундний спалах веселки | всюди |
| `animation`, `color` | наступна анімація, наступний колір із десяти | лампа |
| `sleep` | запускає таймер сну | лампа |
| `focus_toggle` | старт, пауза, продовження | фокус |
| `focus_skip` | наступний відрізок | фокус |
| `focus_reset` | зупинити й обнулити таймер | фокус |

Типово: у режимі агентів — `dismiss`, `mode`, `brightness`; у режимі лампи — `toggle`, `mode`, `brightness`; у фокусі — `focus_toggle`, `focus_skip`, `focus_reset`.

Якщо на подвійний дотик призначено дію, одинарний спрацьовує із затримкою 0,35 с: лампа чекає, чи не буде другого.

**Сигнал агентові.** Агент бачить `signal.count` і `signal.ago` у відповіді `get_status` (MCP) та в `GET /api/status`. Можна сказати агентові: «працюй, доки я не дам сигнал лампою».

**Запит на адресу.** `POST` із JSON `{"device", "gesture", "mode", "state"}` на адресу з розділу «Пристрій». Лише `http://`; відповідь лампа не читає й чекає з'єднання щонайбільше 1,5 секунди.

Розпізнавання жестів (`firmware/src/gesture.h`) і таймер (`firmware/src/focus.h`) не залежать від плати й перевіряються тестами на комп'ютері.

## Сторінка лампи

`http://agentlight.local/` — одна сторінка, 7 КБ у стиснутому вигляді, без зовнішніх файлів. Кожна зміна зберігається одразу.

- **Згори** — колір і стан лампи, кнопка вимкнення світла, перемикач режимів, яскравість.
- **Стан агентів** — картки сесій (проєкт, запит, поточна дія, час), колір і анімація кожного стану з пробою на лампі, часи згасання, дії сенсора.
- **Лампа** — десять готових кольорів і свій, анімація, таймер вимкнення, таймер сну, дії сенсора.
- **Фокус** — час, що лишився, старт і пауза, тривалість роботи й перерви, дії сенсора.
- **Ігри** — вибір гри, правила, хід раунду, рекорди.
- **WiFi** — збережені мережі й додавання нової.
- **Підключення агентів** — команда встановлення для вибраного агента, команди для MCP і REST, кнопки перевірки станів.
- **Пристрій** — версія, пам'ять, сенсор, кількість діодів, тест діодів, типові налаштування, перезавантаження, оновлення прошивки.

## REST

| Запит | Що робить |
|---|---|
| `GET /api/status` | режим, стан, агенти, яскравість, чи вимкнене світло, таймери, сигнал агентові, WiFi |
| `POST /api/status` | виставити стан агента; JSON або параметри запиту |
| `GET /api/debug` | те саме плюс стан плати, сенсор і всі налаштування |
| `POST /api/config` | змінити налаштування; приймає будь-яку підмножину полів |
| `POST /api/action` | `{"action": "on" \| "off" \| "rainbow" \| "clear" \| "defaults" \| "reboot"}` або будь-яка дія сенсора, доступна в поточному режимі (`toggle`, `sleep`, `focus_toggle`, …); `game_tap` — дотик у грі, `game_records` — стерти рекорди; `{"action": "preview", "state": "waiting"}` — 6 с показати вигляд стану |
| `POST /hook/<агент>/<стан>` | хук агента: у тілі подія в його власному форматі, лампа сама дістає сесію, проєкт і дію ([hooks.md](hooks.md)) |
| `GET /install.sh`, `GET /setup/<файл>` | встановлювач і готові хуки для агентів |
| `GET /api/scan` | мережі WiFi поруч |
| `POST /api/wifi` | `{"ssid", "pass"}` — додати мережу і перезапуститись |
| `POST /api/wifi/reset` | `{"ssid"}` — забути одну мережу; без тіла — всі |
| `POST /api/ota/password` | `{"old", "new"}` — задати або змінити пароль оновлення; порожній `new` вимикає оновлення |
| `POST /api/update` | файл прошивки (multipart) і заголовок `X-Signature` (підпис офіційної збірки) або `X-OTA-Password` |

Стан агента:

```sh
curl -4 -X POST http://agentlight.local/api/status \
  -H 'Content-Type: application/json' \
  -d '{"state":"busy","agent_id":"my-agent","name":"проєкт","task":"що попросили","message":"що робить зараз"}'
```

`state` — одне з `idle`, `busy`, `waiting`, `done`, `error`. Решта полів необов'язкові; `name` і `task` запам'ятовуються до наступної зміни. На macOS для адрес `.local` потрібен `curl -4`, інакше запит 5 секунд чекає на IPv6.

Поля `POST /api/config`: `brightness`, `leds`, `ttl_busy`, `ttl_done`, `ttl_attention` (хвилини), `colors` (`{"busy": "#ff5a00", ...}`), `anims` (`{"waiting": "comet", ...}`), `mode` (`agents` \| `lamp` \| `focus` \| `games`), `game` (0–5), `dice` (0–2), `lamp` (`{"color", "anim", "off_min"}`), `sleep_min`, `focus` (`{"work_min", "break_min", "quiet"}`), `webhook`, `touch` (`{"agents": {"tap", "double", "hold"}, "lamp": {...}, "focus": {...}}`).

## Оновлення по WiFi

У пам'яті плати два слоти під прошивку по 1,25 МБ. Нова прошивка пишеться в запасний слот і стає активною після перезавантаження; налаштування, мережі й пароль зберігаються. Під час оновлення лампа світить блакитним.

### Одна кнопка: офіційні збірки

Сторінка лампи → «Пристрій» → «Перевірити оновлення». Якщо є новіша версія, кнопка стає «Встановити X.Y.Z»; про нову версію сторінка каже й сама, смужкою вгорі. Пароль не потрібен.

Як це влаштовано:

1. Тег `vX.Y.Z` у репозиторії запускає `.github/workflows/release.yml`: GitHub Actions збирає прошивку, підписує її і публікує на GitHub Pages разом із файлом `latest.json` (версія, розмір, підпис). Усі версії лишаються в релізах GitHub.
2. Сторінка лампи у твоєму браузері читає `latest.json`, завантажує файл і передає його лампі разом із підписом. Самій лампі інтернет для цього не потрібен.
3. Лампа рахує SHA-256 отриманого файлу й перевіряє підпис ECDSA P-256 відкритим ключем, вшитим у прошивку (`firmware/update_public_key.pem`). Не сходиться — записане лишається неактивним, лампа працює далі на старій версії.

Тому залити чужу прошивку цим шляхом не може ніхто, хоч би й у тій самій мережі.

Випустити нову версію:

```sh
# 1. змінити FW_VERSION у firmware/src/app.h, закомітити
git tag v0.7.2 && git push origin main v0.7.2
```

Закритий ключ підпису лежить у секреті репозиторію `FIRMWARE_SIGNING_KEY` і в автора локально (`~/.config/agentlight/firmware-signing-key.pem`); у репозиторії його немає. Якщо ключ втратити, лампи з нинішньою прошивкою вже не приймуть жодної нової офіційної збірки — лише свій файл із паролем або прошивку по USB.

### Свій файл: з паролем

Для власних збірок. Вимкнено, доки не задано пароль оновлення: сторінка лампи → «Пристрій» → «Залити свій файл прошивки». Перший пароль задається без старого, далі для зміни потрібен поточний.

- **Через сторінку лампи:** вибери `firmware/.pio/build/c3_supermini/firmware.bin` і натисни «Залити файл». Близько 10 секунд.
- **Через PlatformIO:** `AGENTLIGHT_OTA_PASSWORD=... pio run -e ota -t upload`. Близько 40 секунд; macOS може спитати дозвіл на вхідні з'єднання для Python.
- **Запитом:** `curl -4 -H 'X-OTA-Password: ...' -F firmware=@firmware.bin http://agentlight.local/api/update`

### Обмеження

- Прошивка має влазити в слот 1,25 МБ; зараз вона займає 85%.
- Автоматичного відкату немає. Якщо нова прошивка не зможе вийти в WiFi чи зависне, оновити її по повітрю вже не вийде — лише кабелем.
- Підпис не забороняє поставити старішу офіційну збірку: сторінка пропонує лише новіші, але запитом можна залити будь-яку підписану.
- Забутий пароль скидається лише повним стиранням по USB (`pio run -t erase`), разом із мережами й налаштуваннями.
- Пароль іде мережею відкритим текстом (HTTP), тож захищає від випадкових людей у твоїй WiFi, а не від того, хто слухає трафік.

## MCP

`POST /mcp` — Streamable HTTP без сесій і без SSE. Інструменти: `set_status` (ті самі поля, що в REST) і `get_status`.

```sh
claude mcp add --transport http agentlight http://agentlight.local/mcp
```

## Bluetooth

Bluetooth LE ввімкнений завжди й потрібен лише для налаштування WiFi. Клієнт — сторінка `web/setup.html` (Web Bluetooth). Лампа рекламує себе як `AgentLight-XXXX`.

Сервіс `a9e10001-7c1e-4b6f-9d2a-41676e744c69`, значення — JSON до 500 байтів:

| Характеристика | Доступ | Значення |
|---|---|---|
| `a9e10002-…` status | читання | `{"name", "state", "portal", "ssid", "ip", "rssi", "saved": [...]}`, оновлюється щосекунди |
| `a9e10003-…` scan | читання | `{"seq", "list": [...]}` — результат останнього пошуку мереж |
| `a9e10004-…` cmd | запис | `{"cmd":"scan"}`, `{"cmd":"add","ssid","pass"}`, `{"cmd":"forget","ssid"}`, `{"cmd":"forget"}` |

Після `scan` клієнт перечитує характеристику scan, доки не зміниться `seq` (пошук триває кілька секунд). Після `add` і `forget` лампа перезавантажується. Збережених паролів лампа по Bluetooth не віддає. З'єднання без сполучення й шифрування.
